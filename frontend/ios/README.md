# AImesis for families (Flutter iOS)

The family app: one tap per episode of nausea or vomiting, today's medicines with a "Given" tick, history per cycle day, and the CINV Passport (schedule, "Call the ward if…", Belgian resources) in **NL / FR / EN**.

> Demo app, not for medical use. Demo data only.

| | |
|---|---|
| Bundle id | `be.hackingforgood.aimesis.family` (tests: `…family.RunnerTests`) |
| Display name | AImesis |
| Version | `1.0.0` (`pubspec.yaml`), build number from `--build-number` |
| iOS | 15.0+ (as generated by Flutter 3.47), iPhone only, portrait |

## Demo accounts (password `aimesis-demo`)

On the login screen, tap a chip to fill in the account:

- `teen.casus1@demo.aimesis.app`: the teen of Casus 1 (NL)
- `parent.casus2@demo.aimesis.app`: the parent of Casus 2 (FR)
- `parent.casus3@demo.aimesis.app`: the parent of Casus 3 (NL)

Care-team accounts are refused with "This app is for families; the care team uses the AImesis web app."
To add a child, go to Settings › Connect another child and enter a pairing code (`C1-NBL2`, `C2-ALL8`, `C3-IE03`, `C4-DDI7`).

## Run

```bash
cd frontend && flutter pub get          # workspace root
cd ios

# iOS simulator (localhost works in the simulator)
flutter run -d ios --dart-define=API_URL=http://localhost:8080

# real iPhone: must be https (App Transport Security); use the Cloud Run URL
flutter run -d <device-id> --release --dart-define=API_URL=https://mock-api-xxxx.europe-west1.run.app

# fallback: the same app as web at phone width
flutter run -d chrome --dart-define=API_URL=http://localhost:8080
flutter build web --release             # reads ./config.json {"apiUrl": "..."} first, then API_URL
```

`lib/config.dart` reads `API_URL` (default `http://localhost:8080`). On web it first tries `config.json` next to `index.html`, like the care-team web app.
`Info.plist` sets `NSAllowsLocalNetworking`, so plain `http://` works for localhost and the LAN only. Anything on the internet must be `https://`.

## Build for TestFlight (on the Mac)

Before the first upload:
1. In Xcode › Settings › Accounts, sign in with an Apple ID that belongs to the team.
2. In App Store Connect › Apps › **+**, create an app with bundle id `be.hackingforgood.aimesis.family`. If the bundle id isn't in the list, the first run of the script registers it through `-allowProvisioningUpdates`. You can also add it under developer.apple.com › Identifiers.

Then run:

```bash
cd frontend/ios
API_URL=https://mock-api-xxxx.europe-west1.run.app TEAM_ID=ABCDE12345 scripts/testflight.sh
# or: scripts/testflight.sh <API_URL> <TEAM_ID> [BUILD_NUMBER]   (default build number: date +%Y%m%d%H%M)
```

The script:
1. Writes `DEVELOPMENT_TEAM` into `ios/Runner.xcodeproj/project.pbxproj`.
2. Runs `flutter build ios --release --no-codesign --dart-define=API_URL=… --build-number=…`.
3. Runs `xcodebuild … archive -allowProvisioningUpdates` with automatic signing.
4. Runs `xcodebuild -exportArchive` with `scripts/ExportOptions.plist` (`app-store-connect`, `destination=upload`, `uploadSymbols`). This uploads directly to App Store Connect using the Xcode account. For a headless upload, set `ASC_KEY_PATH`, `ASC_KEY_ID` and `ASC_ISSUER_ID` (App Store Connect API key) instead.

`ITSAppUsesNonExemptEncryption = false` is set in `Info.plist`, so TestFlight doesn't ask about export compliance.
Each upload needs a new build number. The default timestamp takes care of that.

### Swift Package Manager

Flutter 3.47 enables SPM by default. `pubspec.yaml` also sets it per project:

```yaml
flutter:
  config:
    enable-swift-package-manager: true
```

The script also runs `flutter config --enable-swift-package-manager` to be safe. There is no `Podfile`, and none is needed. If a `Podfile` ever appears, a plugin without SPM support has been added.

## Code map

```
lib/
  main.dart, app.dart          bootstrap, theme (AimesisTheme), l10n, phone-width frame
  config.dart                  API_URL + web config.json
  state/app_state.dart         session, child, language, passport/episodes, "given" ticks
  services/offline_queue.dart  persistent queue (shared_preferences)
  services/episode_service.dart  stage → (optional severity) → send, retry on resume/pull-to-refresh
  pages/login, pairing, today, log, history, passport, settings, home_shell.dart
  l10n/app_{en,nl,fr}.arb      → generated into lib/l10n/gen (flutter gen-l10n, runs on pub get)
scripts/testflight.sh, ExportOptions.plist
```

Logging: a tap first writes the episode to the phone (`OfflineQueue`). An optional 1–5 face scale closes by itself after 8 s, then the episode is sent with `AimesisApi.logEpisode`. If sending fails, the app shows "Saved on phone, will send when online" and retries on app resume or pull-to-refresh. Retries keep the original tap time (`at`).
